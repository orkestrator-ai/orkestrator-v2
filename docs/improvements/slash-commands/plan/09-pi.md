# 09 — Consolidate Pi commands and qualify headless behavior

Status: proposed. Dependencies: 01–04. [Index](00-index.md).

## Owners

`bridges/pi-bridge/src/agent-session.ts`, `http.ts`, `prompt.ts`, `state.ts`,
`persistence.ts`, and interaction handling. Verify against installed
`@earendil-works/pi-coding-agent` `0.85.1` session/resource/extension APIs.
Do not assume an extension context's `pi.getCommands()` exists on `AgentSession`.

## One inventory implementation

Extract one bounded catalogue builder and call it from attach, refresh,
reattach, and configuration-change paths. Replace the duplicate HTTP builder,
which currently loses scope. Preserve template argument hints and canonical
extension `invocationName` when supplied. Use resource `sourceInfo` for origin;
do not infer project/user scope from name conventions.

Reflect the SDK's execution ordering: extension commands are considered before
skill/template expansion. If an extension and template use the same invocation,
show only the effective executable winner by default, with an explanatory
shadowed record if useful. Do not expose a separate selectable template unless
the executor can address it without the extension intercepting it.

Keep `/skill:name` as Pi's actual skill syntax. Respect whether resource loading
and skill invocation are enabled under the session's existing policy. Do not
load project extensions on the host merely to improve inventory completeness.

## Prompt and completion behavior

Continue using `session.prompt` with `source: "rpc"` for native UI submissions.
Use the exact qualified SDK expansion setting for command versus literal
intent. Keep templates/skills expanded by Pi; Orkestrator should not reproduce
Pi's argument parser or content loading.

An extension may handle a command without a model turn, may emit custom
messages, or may reject before normal turn execution. Ensure acceptance and
completion are represented accurately through `preflightResult`, the prompt
promise, and existing dispatch journal. Produce a durable command outcome even
when no assistant text is emitted. Do not leave an optimistic user message
waiting for a model acknowledgement that will never exist.

If an extension starts subsequent work, qualify the SDK lifecycle signals that
prove it has finished. Do not clear busy state solely because a wrapper handler
returned. Preserve pending interactions and cancellation ownership.

## Headless extensions

Inventory presence is not proof that an arbitrary extension can work without
its terminal UI. Keep the real headless context. Do not set `hasUI` or pretend
to provide interactive methods just to bypass an extension's checks.

Use explicit SDK metadata when it exists. Where the pin exposes no reliable
UI-requirement flag, label the support as unqualified until the extension path
is tested, or handle an attempted invocation with a bounded unsupported-
interaction result. Do not invent automatic detection from source text.
Reusing the existing question/approval adapter is acceptable only for concrete
SDK callbacks it can faithfully answer. A generic custom-widget host is out of
scope. Timeout/cancellation must not synthesize successful interaction answers.

## Reload and busy-state rules

Replace global unbounded `Promise.all` reload fan-out with the bounded lifecycle
from step 04. Qualify whether `session.reload()` is safe during an active turn.
If not, defer resource reload until idle and report `deferred`, while retaining
the old list as stale. Refreshing commands must not abort a background turn.

For each descriptor specify whether it can run only while idle, can queue, or
is an existing runtime action. Default extension commands to idle until their
behavior is qualified; the SDK's ability to execute extensions during streaming
does not mean every extension is safe to run then. Queue templates/skills only
through existing durable submission semantics with stable identity.

## Compact

Remove the mismatch between global `/compact` discovery and session inventory.
Represent compact as an Orkestrator session action, backed by the existing
`/session/:id/compact` operation and its atomic busy guard. Do not send raw
`/compact` to `session.prompt` as though it were a Pi interactive builtin.
Preserve actual compaction status and rehydrate it when the tab returns.

## Tests and acceptance

- Attach and refresh produce identical descriptors and provenance.
- Extension/template collision dispatches the SDK's effective winner.
- Skill, template, extension with a model turn, and extension without one each
  have one accepted invocation and a durable outcome.
- Headless interaction refusal is explicit and leaves no pending approval,
  stuck status, or unhandled promise rejection.
- Literal/workflow mode does not invoke extension/template/skill commands.
- Busy refresh is safe/deferred; commands reload after idle and survive detach.
- Compact uses the action endpoint and cannot interrupt unrelated work.
- Provider generation/restart and inactive-environment tests recover catalogue,
  command result, and pending interactions from authoritative state.
