## Compatibility review

- Claude's installed Agent SDK declarations are byte-identical across this
  upgrade. Query lifecycle, session adoption, background-task controls,
  checkpoint/rewind, partial messages, structured output and model/catalog
  contracts remain compatible. The real-SDK deterministic compatibility suite
  re-proved `AskUserQuestion` parking through `canUseTool` under
  `bypassPermissions`; its compatibility comment now names `0.3.263`.
- Codex was regenerated from the hash-verified `binaries/codex` reporting
  `0.153.4`. Only generated provenance changes: all 706 TypeScript files and
  the schema digest are unchanged. Client methods, server requests,
  notifications, thread items, status/source enums and approval vocabulary
  therefore have no protocol delta. `turn/start.clientUserMessageId` and
  `userMessage.clientId` are present. The credential-free live contract
  re-proved the untouched-thread history fallback; only its explicit
  verification comment was advanced. Historical `0.153.3` explanations remain.
- OpenCode's generated v2 declarations are unchanged. The renderer and backend
  retain flat v2 parameters and authoritative session/status reconciliation.
  The SSE patch was regenerated in a fresh isolated Bun package/cache from
  upstream `1.18.29`, then installed in the workspace. Both v1 and v2 generated
  clients, in both workspaces, contain
  `void reader.cancel().catch(() => {});`. The new patch is byte-identical to
  the old patch because both upstream target files are unchanged; this is a
  verified rebase, not an unverified filename change.
- Pi's `AgentSessionEvent`, agent-core types and thinking-level vocabulary are
  unchanged. The model declaration changes only clarify cache TTL behavior;
  SDK changes remove experimental subpaths outside the bridge's imports.
  Reviewed synchronous event translation, unknown-tool degradation,
  `provider/modelId` encoding, SDK thinking-level support and clamping, and
  per-provider credential status. No adapter change is necessary. `pi-server`
  remains a vendored root as requested, although the `0.85.0` missing-import
  workaround is no longer needed by the coding-agent entrypoint. The root
  vendoring regression was adapted from the removed experimental worker to
  importing the supported SDK in a fresh Bun process from the staged tree. It
  verifies the four staged package versions and the public session exports.
- Cursor's existing exact release remains compatible with agent construction,
  send/cancel, credentials/login child, model effort/fast parameters, nested
  updates, and tool rendering. Exhaustive SDK vocabulary tables typecheck;
  unknown runtime variants still degrade safely. Subagent detachment remains
  tied to the parent run because its nested updates are the observing channel.
- Grok's hash-verified `1.0.13` advertises `--always-approve` globally. An
  isolated process using exactly `--always-approve agent stdio` accepted an
  ACP `initialize` request and remained alive waiting for input. It used empty
  temporary HOME/GROK/XDG directories, disabled automatic updates, received no
  credentials or model prompt, and was terminated and cleaned up afterwards.

## Manual checks still required before release

No paid model turns or interactive authentication flows were run. The unit and
credential-free live checks do not establish end-to-end provider conversation
behavior. On an isolated `dev:test` fixture profile, follow
[`docs/development/agent-testing.md`](../development/agent-testing.md) and test
both local and container sessions where supported:

1. For **each of Claude, Codex, OpenCode, Cursor, Grok and Pi**, start a turn
   in fixture environment A, then switch to environment B so A's chat tree can
   unmount. Let the turn progress or wait for a question/approval. Return to A
   and verify transcript, running/idle status, pending interaction and stop/send
   controls. Reload and confirm the same authoritative state. Answer or decline
   the pending prompt, switch away again, and verify completion on return.
2. Claude: streaming, question parking, abort, resume, model discovery,
   background-task completion and checkpoint/rewind.
3. Codex: a code-mode tool turn proving companion execution, approval denial,
   abort/resume and recovery; run the paid MCP approval canary separately only
   with explicit authorization.
4. OpenCode: native chat and a build-pipeline phase, including streaming,
   question/permission recovery, abort/resume and final phase status.
5. Cursor: login child, tool calls/diff, model/effort switch and cancellation;
   confirm subagent cards become detached when their parent ends and do not
   leave the environment busy after reload.
6. Grok: interactive ACP streaming, tools, cancellation and resume.
7. Pi: native and terminal tabs, model switch, thinking-level clamping,
   compaction, and one signed-in and one signed-out provider status.

macOS signature repair and native execution on macOS/arm64 require their
respective machines. No browser profile was started by this upgrade, so there
is no launcher/profile state to stop or reset.
