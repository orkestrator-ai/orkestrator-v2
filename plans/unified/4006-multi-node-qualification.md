- **Flows and how each is checked** (no provider turn anywhere; evidence holds ids, timings, tiers and counts only):
  - *Open each node*: click its environment in the sidebar; its region (`in-tree-workspace[data-node]`) is the only visible one, no realm frame, its terminal shows.
  - *A leaf's surfaces* (4001's live box): the terminal runs a command (output checked in the renderer's own xterm buffer, not the echo), the files panel lists the file it wrote, a new native agent tab shows its composer (nothing sent), and a browser tab on the fixture server the leaf's terminal started (`PORT=0 bun server.ts`, port read from its output).
  - *Inactive-environment cycle*: `sleep 6; echo cycle-$((40+2))-<nonce>` typed in the leaf's terminal, switch to the command node's environment, wait 9 s, return (output there), reload (output there again, the terminal takes input).
  - *Snapshot-first reload*: wait for the leaf's IndexedDB snapshot, hold the next grant open for 3 s, reload; a MutationObserver installed before the app records when `node-snapshot-preview`, `snapshot-stale-marker` and the live terminal first appear in the leaf's region; the snapshot must paint, marked stale, before the live workspace, then go.
  - *Six-node switching with budget eviction*: three rounds over the six leaves (click to terminal visible), each shown node `live`, the others `warm`; then `ScopeLifecycle.configure` with `memorySource: "estimate"`: budget A (estimate − 2.5 × the per-scope estimate) suspends the least recently shown; budget B (one scope + 1 MiB) takes every hidden node to summary; the default budget back, an evicted node reopens when shown. JS heap after a full GC (CDP) with six warm and with one shown.
  - *Two nodes' previews* (desktop): a browser tab in the command node's environment and one in a leaf's, distinct tab ids; main's `contentView` children are read: only the shown node's preview view is visible, the leaf's sits in the leaf's region, the hidden one keeps no focus after a switch, switching back reuses the same view.
  - *Grant lapse*: the window's latest `open_node_workspace` for the leaf is recorded (workspace id only; browser from the page's responses, desktop from main's `fetch`), `close_node_workspace` revokes it, the terminal and the files panel are used; a new grant must open, the terminal must work, and a marker on `window` proves no reload.
  - *Attention from a hidden node*: the leaf shown once (held), then the command node's environment shown; `terminal_finished` raised on the leaf's environment through an activity-tracked terminal (as in 0002/5001); the row shows "New completed activity" and the window plays a cue (oscillators counted; `Notification` stubbed).

- **Fixes after qualification (2026-11-07).**
  - *Finding 1, desktop leaf preview* (`ca61d7ae8`, `12efe1b97`). Options: (a) the desktop node client caches the node's route from `nodes.gateway(nodeId)` and resolves leaf gateway URLs in the renderer (needs a sync cache, stale on a relay-to-direct rebind until `node-scope-changed`, and the preview store's `resolvePreviewUrl` is not reactive); (b) main resolves, since it owns the node scope's current route. Chosen (b): `createDesktopNodeClient` gains `resolvePreviewUrl` = the canonical address (`desktopNodePreviewUrl`), so the preview store no longer falls back to the window gateway, and the node's preview runtime in main (2009) applies `nodePreviewUrl(getGatewayBaseUrl(record.scope), url)` on every attach and navigation (`BrowserPreviewManagerOptions.resolveAddress`): a loopback address, or another node's gateway preview path, goes through the node's own gateway; with no route (parked mid-reopen) it refuses rather than load this computer's page. This also closes 2009's noted gap (an address-bar preview kept the old gateway origin after a rebind): the next attach follows the route. Live, a second bug showed: the node runtime's authorized requests presented the desktop's default `Origin` (`https://orkestrator.dev`), which a leaf refuses for a workspace grant ("Origin not allowed"); the runtime now presents the node gateway's own origin (`nodePreviewRequestOrigin`, `requestOrigin` through `initializeBrowserPreviews`). Then the leaf answered as the command node does for the same request: a manual URL on an unregistered port is "not an available preview service of this environment" (M2, on every node), so the spec registers its fixture server as a preview service of the leaf's environment (`ee73894da`); the tab then migrates to a service preview over the leaf's tunnel and shows the leaf's page. Not done: a relayed leaf's address-bar preview (its base has a path prefix, which main's gateway-preview checks do not accept; realms had the same limit). Dev-only edge: a leaf page on the same port as a dev renderer served over loopback HTTP is refused by `resolveBrowserAddress`'s own-renderer check, because the canonical address is sent unchanged.
  - *Finding 2, desktop terminal after a grant lapse* (`ffdf8deae`). Root cause: the first write after the revoke was refused (HTTP 401) or held back while main parked the client on the dropped stream ("awaiting a verified route"); the shared terminal input sequencer treats any failed send as an ambiguous loss and fences the terminal until the user resumes, and nothing re-armed it, so the reopened grant (same connection id, `rebindWorkspace`; the window's event mapping was fine) carried no input. The browser kept working because its leaf terminals write over the WebSocket opened before the revoke. Fix: `BackendHttpClient` marks a request the backend never ran (`RequestNotSentError`: 401 before dispatch, or a parked route) and, on a client whose credential is renewed for it (a workspace connection, `onCredentialRefused`), the sequencer's sends wait for the next `retarget` and resend (at most 3 credentials, within the sequencer's send deadline), so order and the fence for real ambiguous losses are unchanged. A refused workspace credential (an invoke 401, or a 401 on the event stream, which before set "authentication-required") now reopens the grant at once (`ConnectionManager.workspaceUnavailable`, once per lapse). Test: `apps/desktop/tests/node-scope-grant-lapse.test.ts` (real connection manager, node scopes and grant tracking against a fake leaf; fails without the fix).
  - *Smoke regression, capped file tree at 390 px* (`e46872643`). Bisected by reading the range to `56604e224` (3006: "the selection survives a reload", a stated visible change): after a reload the environment is selected again while the phone drawer opens on first load, and choosing that row changes no selection, which is the only thing the drawer closed on. Fix: `noteDrawerNavigation()` (`lib/mobile-shell.ts`) from `HierarchicalSidebar`'s environment choice and `useFederatedEnvironmentActions.open`; `MobileAppShellLayout` closes on it. Unit test in `MobileAppShellLayout.test.tsx` (fails without the fix).
  - *Finding 5, a changed command-node origin* (`b489a2e4d`). Pre-existing at base `148e9ad0a` (same code): `backend.init()` starts the node links before the gateway binds, so `attach_controller` carried no portal origins (`setPortalOriginsSource` is set after `startGatewayServices`), and nothing resent them until the next reconnect. `update_node` was not the path. Fix: `setPortalOriginsSource` calls `NodeService.portalOriginsChanged()`, which re-sends the attachment on every connected link (`NodeLink.reattach`). Not covered: an origin that changes later at runtime (the managed web client's URL), which is sent on the next connect. Test in `node-service.test.ts`.
  - The spec's node switch now moves the pointer off the sidebar before and after a click: a resting pointer opened a row's hover card, which covered the next row and, as an overlay, hid the native previews (`ee73894da`).
