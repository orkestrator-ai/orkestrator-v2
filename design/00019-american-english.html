00019 · Switch the product voice to American English

To do Medium Copy Evidence 0 / 8 images

Problem

The decision is American English. The UI is already mostly American (Favorite, Color, Initializing, Customize), so the work is in the documents and a few display strings: PRODUCT.md states British English, DESIGN.md spells “colour” 21 times (including rule names such as the Outcome and Mode color rules), and a handful of strings say “cancelled” or “cancelling”. The cancelled value used as a status in code (500+ occurrences) is data, not copy.

Voice: plain, precise, factual British English.
PRODUCT.md, Brand Commitments. Decision: use American English (user, 2026-11-14).

Approach

  1. Edit the voice line in PRODUCT.md to American English and re-read the whole file for British spellings.
  2. Rewrite British spellings in DESIGN.md prose and rule names (for example “Colour” becomes “Color”, “greys” becomes “grays”). Keep the front-matter token names unchanged.
  3. Change displayed “cancelled/cancelling” to “canceled/canceling”. Do not rename the status values, type names, test ids or persisted data that use cancelled.
  4. Check each changed string against tests that assert on it (grep -rn "was cancelled" apps/web/src and similar) and update the tests with the string.
  5. Check the public site (apps/web-public) and the CLI’s help and output for user-visible British spellings.
  6. Leave code comments alone unless a file is already being edited.
