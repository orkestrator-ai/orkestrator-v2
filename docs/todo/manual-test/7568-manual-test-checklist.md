expected outcomes come from the source to-do as it stood at `53340356c`.
Where an agent part of the same task remains, the source to-do keeps it,
usually as `blocked (waits on 7568: <source> task N)`.

**Decisions.** How to report a result:

- Tick the box and record the result where the item says: normally the
  source to-do's evidence or Assumptions and decisions section, or a reply
  to the coordinator (recommended). Pros: the evidence lands next to the work
  it unblocks. Cons: needs a commit or a message.
- Write the result under the item here. Pros: one place to edit. Cons: an
  agent still has to carry it into the source to-do before acting on it.

The agent that acts on a recorded result updates the source to-do and removes
the item from this file in the same change.

   provider's host login copied in:
   `mise run dev:test --profile perm-rules-<agent> --fixture --credential-source <agent> --agent-platforms <agent>`.
   Use `claude`, `codex`, `grok`, `opencode` or `pi`.
2. Wait for `mise run dev:status --profile perm-rules-<agent> --json` to show
   `status: "ready"`. Open its `browserUrl`, and sign in through the
   `loginCommand` it prints.
3. Open Settings → Permissions and note the paths under "Rules outside
   Orkestrator". Record `shasum -a 256` of each file that exists for this
   provider: the account's Claude `settings.json`, the Codex `rules/` folder

   use.
