### Decisions (2026-11-07)

- **Argument schemas declare every key a handler reads** (internal callers included: Control MCP tools, `context.invoke`, node links). Options: type every key (`Schema.String` gives the same "Expected x to be a string" text) or `optionalKey(Unknown)` for keys the handler checks itself. Per slice:
  - `system`, `agent-servers`, coordinator project part: keys read with `asString`/`asNonBlankString` are typed (same text; the blank check stays in the handler); keys read leniently, nullable, bounded, or with their own message are `optionalKey(Unknown)` (`channel must be stable, beta or unstable`, `scheduleId is required`, `refresh must be a boolean`, the manifest cursors, `provider`, `agent`, `ensureAgent`, `models`, `seed`, `forceRefresh`, `previous`, the Control MCP `scope`/`input` records). `timeoutMs` is `Schema.Finite`. On the coordinator launch, delegation and build/review starts, `requestId`/`environmentId`/`tabId` are typed although the handler checks `scope` first: only the order of errors changes, and only when two arguments are wrong at once.
  - `nodes` and the coordinator controller part: every key is `optionalKey(Unknown)`. Typed keys would change which error a caller sees first (`create_controller_pr` checks `targetBranch` before `projectId`; the credential commands check `controlMcp` first; `*_coordinator_node_*` check `scope` first), would turn some async rejections into synchronous throws, and `controller_multi_review_surface` must keep its "Expected surface …" text, which an older command node matches. Nothing accepted today is refused and no key is required, which leaves stage 2 room.
  - Nested records (`scope`, `input`, `launch`, `options`, `target`, `to`, `request`, `update`) are not typed and keep all their keys.
- **Strict handlers made tolerant:** every `assertOnlyKeys` handler: all 51 `nodes` handlers, the system/host/bug-report/disk-usage ones, the 9 in tools, 2 in servers, `await_bridge_ready` and both peeks in `commands-registry-pr.ts`, the 5 in `commands-registry-projects.ts`, `watch_coordinator_pull_request` and `hide_coordinator_work`. The unknown-key checks inside `parseBackendProfileUpdate` and `parsePortalLayoutUpdate` no longer fire because decoding strips first. **Kept strict on purpose:** each OpenCode catalogue entry's nested check (a value, not argument keys).
- **Trusted in-process values on symbol keys.** Two values travel as symbol keys on the arguments, which a decode drops (it builds a new object): the scheduled-job actor (`SCHEDULE_ACTOR`) and a coordinator's delegation presentation on `launch_control_job`/`launch_native_agent_job`. A `beforeDecode` wrapper moves the symbol onto the invocation and the handler restores it (`carryCoordinatorDelegationPresentation`/`restoreCoordinatorDelegationPresentation` in `coordinator-delegation-authority.ts`; the system registrar's own wrapper), so only in-process callers can still set them; pinned by backend tests. Rejected: a symbol field in the schema (breaks the JSON Schema export); wrapping the context (identity risk).
