- **Root cause and fix, 2026-11-04.** Two budgets were too small for this journey. The 120 s test budget is the original symptom: passing runs on arktech-mini took 119–123 s. The 5 s assertion is the symptom on beelink. In the failed isolated run at `b16b51da1`, the first `folder.load-failed` was logged 95 ms after that assertion began, but the page's next one was logged 17.5 s after its 500 response, 4 ms after the assertion failed, with the failure snapshot showing `Loading folder…`. The assertion itself took 17.7 s rather than 5 s, which is consistent with a stalled renderer (the page showed host CPU at 100%), so its last check came before the page had handled a response it had already received. The fix gives this case a 240 s test budget and 30 s for each tree assertion once the rows exist. No assertion was removed. What the page was doing during the stall was not investigated.
