# 7011 · Typed backend events in the contract

- **Report:** [§11.1](../../docs/reports/unified-federation.md#111-where-skew-actually-is), [§11.2](../../docs/reports/unified-federation.md#112-design), [§6.4](../../docs/reports/unified-federation.md#64-events-must-carry-their-node)

- **Parallel with:** all other Phase 7 items and Phases 2-6
- **Size:** M
- **Track:** C (contract)

## Goal

Every backend event has one definition with a payload schema and a domain, is listed in the manifest, and is received through a typed `listen(def, handler)`.

## Current state (verified 2026-11-07)

- `BackendEmit = (event: string, payload: unknown) => void` (`commands-context.ts:23`).
- There is no central list of event names. About 29 literal `emit("…")` names exist, plus constants (for example `BACKEND_PROFILE_CHANGED_EVENT`, `ENVIRONMENT_ATTENTION_EVENT`). The report's ~45 includes dynamic names; recount from the manifest.
- `RESOURCE_KINDS` (`packages/protocol/src/resource-events.ts:12-97`, 28 kinds) is already a tolerant reader.
- Relay rules: `UNRELAYABLE_EVENT_PREFIXES` (`packages/protocol/src/node-events.ts:39`).

## Work

- [x] `defineEvent` for each event, starting with `resource-changed`, `environment-attention` and the native agent activity events.
- [x] Typed `emit(def, payload)` on the backend, validating in development and tests only. Dynamic names (for example per-terminal `terminal-output-<key>`) are defined as event families with a name pattern.
- [x] Add events to the manifest. The untyped-events count joins the shrink-only baseline from [1011](1011-contract-policy-and-docs.md).
- [x] `NodeClient.listen(def, handler)` gives typed payloads; the web side uses it in scoped stores.

- [x] Backend: the manifest's `events` section (entries, default to `BACKEND_EVENTS`, duplicate and covering-family problems, payload change is drift); every existing emit test passes with the checked emitter.

## Notes

### Event count (2026-11-07)

The manifest lists **44 events** in 18 domains: 41 named events and 3 families (`terminal-output-*`, `claude-state-*`, `relayed-node-event:*`). This replaces the report's estimate of about 45. Not counted: the gateway's own control frames (`gateway.connected`, `gateway.reconcile-required`, `gateway.cursor`, `gateway.keepalive`, the legacy `relayed-node-event` frame), which the gateway writes itself rather than through `BackendEmit`, and the desktop main process's own events (`menu-keyboard-shortcuts`, `app-shortcut`, `browser-preview-*`, `ssh-auth-prompt`, connection lists), which never pass the backend.

### Decisions (2026-11-07)

- **Layout.** `packages/protocol/src/contract/domains/<domain>/domain.ts` (`<camel>Domain = defineDomain({ name, version: 1 })`) and `.../events.ts` (the definitions and a `<DOMAIN>_EVENTS` list), with `contract/domains/events.ts` as the one aggregate (`BACKEND_EVENTS`, `backendEventFor(name)`) and the one new `exports` subpath (`./contract/domains/events`). The per-domain `domain.ts` is what 1010 and 7001-7009 add their `commands` next to (1009's `client-usage.ts` already imports `systemDomain`). Each domain is version 1; defining a domain does not change the hello, because the registry advertises only domains with a defined command (1003).
- **Domain per event.** `system`: `resource-changed`, `backend-profile-changed`, `host-maintenance-updated`, `control-mcp-state-changed`. `environments`: attention, setup started/complete, renamed, activity recorded. `docker`: container lifecycle, host reachability. `coordinator`: wake attention. `native-sessions`: session activity, async question. `claude-tmux`: `claude-tmux:event`, `tmux-agent-usage`, `tmux-prompt-detected/-cleared`, `claude-state-*`. `terminals`: `terminal-output-*`. `nodes`: registry, status, SSH prompt, summary, outcomes, portal layout, project copy, `relayed-node-event:*`. `node-mail`: outbox ready, action requests. `ticket-sync`: outbox ready, status. `git`: change projection, diff stats, worktree snapshots. `accounts`: accounts changed, auto-switched, coordinator switched. Plus `design`, `pull-requests`, `web-annotations`, `mcp`, `previews`, `agent-servers` (Claude model catalog) with one each.
- **Event families** (`defineEventFamily({ domain, prefix, payload, key? })` in `contract/event.ts`, an extension of 1002's module). Options: an overload `emit(family, key, payload)`, or `family.at(key)` returning an ordinary `EventDef`. Chose `at(key)`: emit and listen keep one shape (`emit(terminalOutputEvents.at(id), …)`, `client.listen(terminalOutputEvents.at(id), …)`), and the member carries `family` so checks and the manifest find the family. `at` does not check or freeze, because terminal output calls it per chunk; the key is checked by the backend's development and test validation (`hasValidEventKey`). The prefix is kebab case ending in `-` or `:`; the default key pattern is the backend id shape, which covers session ids, container ids and node ids. A family cannot cover another event's name (test and generator check).
- **Name pattern relaxed** to allow one `:` suffix (`/^[a-z][a-z0-9-]*(?::[a-z][a-z0-9-]*)?$/u`), because `claude-tmux:event` predates the contract and renaming it would break every older client. 1002's test cases still fail; `a:b:c` and `a.b` are refused too.
- **`BackendEmit` is definition-only**: `<E extends AnyEventDef>(def: E, payload: PayloadOf<E>) => void` in `apps/backend/src/core/backend-emit.ts` (re-exported from `commands-context.ts`). Options: an overload keeping `(name: string, payload: unknown)` during migration (what the plan suggested), or converting every site now. Converting was possible in one pass (about 60 production sites plus 20 services with their own `emit` option type), so the string form was never kept; an overloaded type would also have made every untyped fixture lambda an implicit-any error (1003's experience). The transport underneath is a `BackendEventSink = (event: string, payload: unknown) => void` (the gateway, `OrkestratorBackend`'s `emit` option, test recorders), and `createBackendEmit(sink)` is the only bridge.
- **Validation.** `backendEventValidationDefault`: `throw` under `NODE_ENV=test`, `log` in development (the `contract` area's `event.invalid`, name only, and the event is still delivered, so a schema slip never stops a dev backend's background loop), `off` otherwise. A check refuses a payload that does not encode against its schema, a family member with an invalid key, and a definition missing from `BACKEND_EVENTS` (so nothing can be emitted that the manifest does not list). The payload is passed through unchanged, never the encoded copy, as with command results (1003).
- **Test fixtures.** A fixture that records emits by name wraps its recorder in `eventSink((event, payload) => …)` (the same pattern as 1003's `registrarFrom`): it is the checked emitter over the recorder, so assertions keep comparing names and every test also validates every payload it causes. About 60 test and support files were wrapped mechanically (outside a strict reading of this item's files, all a pure wrap); a fixture that ignores events keeps `() => {}`. The full backend suite surfaced the payload mismatches: the schemas were corrected (optional `previous_state`, the per-kind `claude-tmux:event` union) rather than any test loosened.
- **Payload schemas.** Each pins the fields receivers route on (ids, revisions, generations, `kind`) and every top-level key an emitter sets; model-shaped parts (an environment, a PR monitor state, a node status, a container lifecycle snapshot) are `Schema.ObjectKeyword` until the models converge on protocol schemas (7010). TypeScript's excess-property check on literal payloads at the emit sites forced the top-level keys to be complete. Open vocabularies stay `Schema.String` (resource kind, native session cause, account platform and switch reason, activity kind) so a newer backend's value is not refused; closed ones a reader already refuses stay literal (attention `reason`, SSH prompt `state`, the `claude-tmux:event` kinds). Fields an older backend may not send are optional (the design hint's `generation`), because a client decodes every peer's payloads.
- **`Schema.optional`, not `Schema.optionalKey`, for optional payload fields** (deviation from 1001's rule for command schemas, recorded in `version-compatibility.md`): emitters set absent fields to `undefined` (`logical_session_key: event.logicalSessionKey`), which JSON drops but `optionalKey` refuses. The JSON Schema export is `anyOf [T, null]`; the digest is stable either way.
- **Typed listen delivers the payload as sent**, after it decodes. Options: deliver the decoded value (unknown keys stripped) or the original. Chose the original: a schema that names only the routing fields then hides nothing a migrated handler reads, and `PayloadOf<E>` still types exactly what the schema checked. A payload that does not decode is dropped and logged by name only (`contract` `listen.payload-invalid`); the issue text is not logged because Effect's message may quote a value.
- **`NodeClient.listen(def, handler)`** is on the protocol interface (`node-client.ts`) and built in every web client (`command-client`, `browser-node-client`, `desktop-node-client`, the leaf lease in `node-clients.ts`, `FakeNodeClient`) by `typedListen(listenRaw)` (`apps/web/src/lib/node-scope/typed-listen.ts`) over protocol's `listenEvent`. 2011 adds the typed `invoke(def, args)` and `scope.domain(def)` beside it; `listen` needs no negotiation, since an event's name never changes within a domain version. Adopted in two scoped stores: the preview service store (`previewServicesChangedEvent`) and the design canvas controller (`designCanvasChangedEvent`). The rest of the web's `listen(name, …)` call sites move domain by domain with Phase 7 (each domain item converts its listeners when it types its commands).
- **Untyped-events count.** There is no string emit to count: `BackendEmit` refuses a name at compile time, and the test-time check refuses a definition not in `BACKEND_EVENTS`. So the shrink-only baseline needs no events entry; the manifest records `counts.events` (44) and the full `events` section, and `--check` fails on any added, removed or changed event (`event added|removed|changed: <name>`). `scripts/contract-check.ts` (1011) is unchanged.
- **Manifest shape.** `events[<name>] = { domain, payloadDigest }`; a family is `events["<prefix>*"] = { domain, family: true, prefix, key, payloadDigest }` (`key`: the key pattern's source). Digests as for commands (1006). `counts` gains `events`. The generator reports a duplicate key and a family prefix covering another event.
- **Effect.** Effect Schema for every payload, `Schema.decodeUnknownResult`/`validateEventPayload` (`Result`) in `listenEvent` and the backend check, `Data.TaggedError` (`InvalidEventPayloadError`, 1002) as the thrown test failure. Deliberately not Effect: `createBackendEmit`, `typedListen` and the families are plain functions and frozen objects; emit is a synchronous hot path (terminal output) and needs no runtime, services or fibers.
- Aggregate suite left to review preparation. Before the commit the whole backend suite ran once (20,233 pass; the failures were fixtures recording by name, all fixed and re-run: 1,257 pass in the 36 affected files, plus `tests/tmux-poll-signal.test.ts`); the 15 `tests/standalone.test.ts` failures need `apps/backend/dist/main.js` (not built in this worktree) and are not caused by this item.
