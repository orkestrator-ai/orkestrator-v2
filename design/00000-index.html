How each task works

  1. Capture before. Before editing, capture every before slot on the task page from unmodified code.
  2. Fix. Follow the task’s approach and record decisions in its Notes. Keep to the task’s scope.
  3. Capture after. Re-capture each slot with the same profile, data, theme, viewport and file name pattern.
  4. Compare. Open the task page. Each slot shows before and after side by side, and the Evidence badge counts how many of the images exist. Write what changed in Notes.
  5. Verify and close. Run the verification commands, tick the checklist, set the status to Done here and on the page.

How to capture before and after images

Use the real renderer against an isolated backend, never a production Orkestrator instance and never this checkout as the project. On Linux, run the launcher without the desktop’s display variables so no window opens on the host desktop. 

# 1. Start an isolated profile (long-lived; run it in the background or another terminal)
env -u DISPLAY -u WAYLAND_DISPLAY mise run dev:test --profile design-00001 --fixture --headless

# 2. Discover the browser URL and sign in (never print or save the gateway token)
mise run dev:status --profile design-00001 --json     # use browserUrl
mise run dev:login  --profile design-00001            # open the single-use loginUrl

# 3. Capture with Playwright at the viewports named on the task page
#    desktop 1440x900, narrow 390x844, deviceScaleFactor 1
# 4. Stop and reset when finished
mise run dev:stop  --profile design-00001
mise run dev:reset --profile design-00001
// capture.ts, run from the repo root with bun (keep it outside the repo or delete it afterwards)
import { chromium } from "@playwright/test";

const [url, out, width = "1440", height = "900"] = process.argv.slice(2);
const browser = await chromium.launch();
const page = await browser.newPage({ viewport: { width: Number(width), height: Number(height) } });
await page.goto(url);                 // a page that is already signed in; see dev:login
// ...navigate to the state described on the task page...
await page.screenshot({ path: out }); // or page.locator(...).screenshot({ path: out })
await browser.close();
  • File names. design/images/NNNNN/before-<slug>-<desktop|narrow>.png and after-…, exactly as printed under each slot.
  • Same conditions. Same profile and fixture data, same theme and zoom, same viewport, same state. Capture the whole surface, or the element if it is small.
  • Hard-to-reach states. Force errors with Playwright (block a request) or a throwaway profile. If a state truly cannot be reached, say so in Notes and capture the nearest reachable state; do not fake it.
  • Safety. No gateway tokens, credentials, prompts, terminal contents or file contents in screenshots. Keep each PNG well under 1 MB where possible.
  • Fresh profile dialogs. A new profile shows a Claude sign-in dialog and a Docker reachability notice; dismiss them before capturing.
