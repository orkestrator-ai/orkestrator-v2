- **Hypothesis:** `runBridgeScript` runs `spawnSync(process.execPath, ["-e", …], { timeout: 60_000 })` and treats any non-zero `status` as failure. A `null` status after 58ms cannot be the 60-second timeout: `spawnSync` gives `status: null` either when the child is killed by a signal or when the spawn itself fails (`result.error`, e.g. `EAGAIN` under process pressure), and both leave `stderr` empty. The helper reports neither `result.signal` nor `result.error`, so this run cannot tell them apart.
- **Root cause:** every `the bridge process` and `the host execution posture` spawn test starts a cold `bun -e` child synchronously, under Bun's default 5,000 ms per-test budget (the 60 s `spawnSync` timeout never applied, because the outer budget is smaller). Child startup cost scales with host load: locally each case takes 13–200 ms idle and up to 1.65 s with 3× CPU oversubscription, and the opt-in case runs three children back to back. On a CI runner shared with the root and workspace groups, the budget expired while a child was still running. Bun then kills that test's child (`killed 1 dangling process`), so `spawnSync` returns `status: null` with empty stderr. That is exactly the reported message. Shrinking the budget reproduces it deterministically: `bun test src/config.test.ts --preload ../../tests/setup-node.ts --timeout 25` fails the same four tests with `bridge script exited null: ` / `Received: null`, `this test timed out`, and `killed 1 dangling process`. The CI evidence (5,000 ms timings plus the dangling-process kill) matches this. The original 58 ms local record has no surviving log to confirm a signal or a spawn error, so the new helper now reports both.
- **Fix:** this branch. In `bridges/cursor-bridge/src/config.test.ts`, the spawn tests use an async `runBun` helper (`Bun.spawn`, `stdin: "ignore"`, a 20 s child deadline with `SIGKILL`). Each spawn test has an explicit 30 s budget (`PROCESS_TEST_TIMEOUT_MS`) sized for cold process starts under aggregate load. The child deadline sits inside that budget, so a hung child fails with its exit code, signal, deadline and stderr instead of an opaque `null`. The three opt-in values, which are independent fresh processes because `sandboxEnabled` is frozen at import, now start concurrently instead of one after another. No assertion was removed or loosened.
